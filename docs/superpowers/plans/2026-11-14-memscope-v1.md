# MemScope v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local desktop tool that captures Android heap dumps (on demand and at startup milestones from before `Application.onCreate`), and shows them as a collapsed dominator tree from GC roots with retained sizes, a memory timeline, snapshot diff and rule-based findings.

**Architecture:** One Kotlin/JVM Gradle multi-module project (`device`, `capture`, `analysis`, `server`) running as a single local HTTP server that also serves a static no-build web UI. Startup capture drives the app over JDWP (JDI) and invokes `Debug.dumpHprofData` at breakpoints. Analysis parses hprof with Shark into primitive-array indexes and computes dominators itself.

**Tech Stack:** Kotlin 2.x on JDK 17, Gradle 8.9 (Kotlin DSL), JUnit 5, kotlinx.serialization, Ktor (server, CIO or Netty), Shark `com.squareup.leakcanary:shark-graph` + `shark-android` (latest 2.x), `jdk.jdi`, plain HTML + ES modules. Fixture app: Android Gradle Plugin, Kotlin, minSdk 29.

**Spec:** `docs/superpowers/specs/2026-11-14-memscope-design.md`. Spike results: `spike/FINDINGS.md` (Task 0). Executors read both. Where FINDINGS contradicts this plan on a device/JDI/Shark fact, FINDINGS wins; note the deviation in the commit message.

**Out of this plan:** Version 2 (Perfetto allocation recording, allocation timeline, alloc sites). It gets its own plan after v1 works, using spike part C.

## Global Constraints

- Root package `dev.memscope`. Fixture app package `dev.memscope.fixture`.
- Host: macOS, JDK 17, Gradle 8.9. `ANDROID_HOME` is not set: locate the SDK at `~/Library/Android/sdk`, then `ANDROID_HOME`/`ANDROID_SDK_ROOT`, then `adb` on `PATH`.
- No Node, no Python, no native code. UI has no build step.
- The repository path contains spaces. Every script and process invocation must quote paths / pass argument arrays, never a concatenated shell string.
- Target emulator: `emulator-5554` (API 37, arm64, `user` build). Never start/kill emulators or touch other installed apps.
- Supported Android: 10+ (API 29+).
- Every device operation has a timeout, reports progress, and fails with `DeviceException(kind, message, hint)` where `hint` tells the user what to do. No operation may block indefinitely.
- The app must never be left waiting for a debugger: `am clear-debug-app` and forward removal run on success, failure, cancel, and on next server start after a crash.
- Analysis never allocates one JVM object per heap object: per-object data lives in `IntArray`/`LongArray`. Performance target: 1 GB dump analysed in under 5 minutes with `-Xmx6g`; results cached on disk and reused.
- Session data lives in `~/.memscope/sessions/<id>/` (override with env `MEMSCOPE_HOME`, which tests must set to a temp dir).
- Tests needing the emulator are tagged `@Tag("emulator")` and run with `./gradlew emulatorTest`; `./gradlew test` runs without a device.
- One active session at a time.
- Commit after every task step that says so; conventional commit messages.

## Review Focus

1. **Device disconnects or adb dies mid-dump/pull** → job fails within its timeout with a hint ("device disconnected…"), partial local file deleted, debug-app cleared when the device returns. (Tests: Task 1, Task 6, Task 9.)
2. **App crashes or is killed during a startup session** (JDI `VMDisconnectEvent`) → session ends as "app exited at <milestone>", snapshots already pulled are kept and usable, cleanup runs. (Task 9.)
3. **`Debug.dumpHprofData` fails inside the app** (storage full, cache dir missing, app itself near OOM) → the JDI invoke returns an exception; the milestone is marked failed with the Java exception message, the app is resumed and the session continues to the next milestone. (Task 9.)
4. **Truncated or corrupt hprof** (pull interrupted, zero-length file) → analysis fails with a clear error naming the file; no stale cache is written; the UI shows the snapshot as "unreadable" with a re-capture hint. (Task 5, Task 7.)
5. **Selected package is not debuggable or not installed / `run-as` denied** → refused before any state is changed on the device, with a hint naming the cause. (Task 1, Task 6.)

### Task 3: `analysis` — dominators and retained sizes (pure algorithm)

**Files:** `analysis/src/main/kotlin/dev/memscope/analysis/Dominators.kt`, test `DominatorsTest.kt`.

**Interfaces — Produces:**

```kotlin
/** Graph in CSR form over nodes 0 until n. Super-root is the virtual node `n`. */
class Graph(val nodeCount: Int, val edgeOffsets: IntArray /* size n+1 */, val edgeTargets: IntArray, val roots: IntArray)
object Dominators {
  const val UNREACHABLE = -1
  /** idom[i] in 0..n (n = super-root) or UNREACHABLE. Iterative Cooper–Harvey–Kennedy; no recursion (stack-safe for deep graphs). */
  fun immediateDominators(g: Graph): IntArray
  /** retained[i] = shallow[i] + sum of retained of dominator-tree children; 0 for unreachable. */
  fun retainedSizes(idom: IntArray, shallow: IntArray, nodeCount: Int): LongArray
  /** children of each node (and of super-root at index n) in CSR form, each list sorted by retained desc. */
  fun childrenCsr(idom: IntArray, retained: LongArray, nodeCount: Int): Pair<IntArray, IntArray>
  /** BFS parent from the roots (shortest path), UNREACHABLE if none, nodeCount for roots. */
  fun bfsParents(g: Graph): IntArray
}
```

Decisions: weak/soft/phantom/finalizer `referent` fields are not edges. Class objects' static fields are edges from the class object. Shallow size of a class object includes its static field storage. `nativeEst` comes from the `sun.misc.Cleaner` → `thunk` → `this$0` (`NativeAllocationRegistry`) → `size & ~1L` chain attributed to `Cleaner.referent`, summed per owner (FINDINGS section B; reimplement, do not call Shark internals); fall back to Bitmap `mWidth*mHeight*4` only when a Bitmap has no cleaner.

Added after the spike (an empty app's dump is ~35 MB of zygote/boot-image objects): `HeapIndex` also carries `val heapKind: ByteArray` (per object: 0 APP, 1 ZYGOTE, 2 IMAGE, 3 UNKNOWN) taken from the hprof `HEAP_DUMP_INFO` records if Shark's streaming reader exposes them (check `StreamingHprofReader`/`HprofRecordTag.HEAP_DUMP_INFO`); if it cannot be obtained in a reasonable way, fill with UNKNOWN and say so in the report. Add a test that the fixture's planted arrays are APP and `java.lang.Object` class object is not APP (skip that assertion if UNKNOWN).

### Task 5: `analysis` — snapshot query facade and tree model

**Files:** `Snapshot.kt`, `TreeModel.kt`; tests `SnapshotTreeTest.kt`, `SnapshotDetailsTest.kt`.

**Interfaces — Consumes:** `HeapIndex`, `IndexCache`. **Produces** (all `@Serializable`; these are also the server's JSON shapes):

```kotlin
enum class RowKind { CATEGORY, CLASS_STATICS, THREAD, OBJECT, GROUP, SHARED }
data class TreeRow(
  val ref: String,              // opaque, stable within a snapshot: "root" | "cat:<name>" | "obj:<denseIndex>" | "grp:<parentRef>|<classIndex>"
  val kind: RowKind, val label: String, val edgeLabel: String?, // field name, "[i]", or "via N hops"
  val className: String?, val count: Int,                      // count > 1 only for GROUP
  val shallowBytes: Long, val retainedBytes: Long, val nativeEstBytes: Long,
  val percentOfHeap: Double, val childCount: Int, val isAppCode: Boolean)
data class TreePage(val rows: List<TreeRow>, val total: Int)
data class HeapSummary(val reachableBytes: Long, val unreachableBytes: Long, val nativeEstBytes: Long, val objectCount: Int, val classCount: Int)
data class PathStep(val ref: String, val className: String, val edgeLabel: String?)
data class FieldValue(val name: String, val type: String, val value: String, val ref: String?)
data class ObjectDetails(val ref: String, val className: String, val shallowBytes: Long, val retainedBytes: Long, val nativeEstBytes: Long,
  val pathFromRoot: List<PathStep>, val fields: List<FieldValue>, val referrers: List<PathStep>, val referrerCount: Int,
  val rootsReaching: List<PathStep>)          // filled only for children of the Shared row, max 10
data class ClassStat(val className: String, val instanceCount: Int, val shallowBytes: Long, val retainedBytes: Long, val isAppCode: Boolean)
class Snapshot private constructor(...) : AutoCloseable {
  companion object { fun open(hprof: File, appPackagePrefixes: List<String>, progress: Progress = ...): Snapshot }
  val index: HeapIndex
  fun summary(): HeapSummary
  fun children(ref: String, offset: Int = 0, limit: Int = 25): TreePage
  fun details(ref: String): ObjectDetails
  fun classes(): List<ClassStat>             // retainedBytes = sum of retained over instances whose dominator-tree ancestors contain no instance of the same class
  fun instances(className: String, offset: Int, limit: Int): TreePage
  fun revealPath(ref: String): List<String>  // refs from "root" down to ref, for expanding the tree to an object
}
```

Added after the spike: `HeapSummary` also has `val appHeapBytes: Long` (reachable shallow bytes with `heapKind == APP`; equals `reachableBytes` when heap kinds are unknown) and `TreeRow` also has `val appHeapBytes: Long` (retained bytes within the subtree that are APP heap). `percentOfHeap` stays relative to `reachableBytes`. The UI shows a "hide system heap" toggle (default on) that sorts and sizes rows by `appHeapBytes` and hides rows where it is 0.

Tree rules: `children("root")` returns categories in this order when non-empty, sorted by retained desc: `Static fields` (root kind CLASS; children are `CLASS_STATICS` rows per class, whose children are that class object's dominator children labelled by static field name), `Thread stacks` (children `THREAD` rows; under each, objects rooted by that thread's frames/locals), `JNI globals`, `Other roots`, `Shared (held by several roots)` (dominator children of super-root that are not roots). Category retained = sum of its children. Sibling objects of the same class numbering ≥ 10 under one parent collapse into one `GROUP` row (label `"1,240 × android.graphics.Bitmap"`, retained = sum); expanding the group pages through the instances. Edge labels and field values are read lazily from the hprof by object id (not stored in the index). Path/field lists capped: `referrers` 100, array elements 100.

Default milestones (ids fixed; hook methods are filled from `spike/FINDINGS.md` A.2 in Task 0 Step 2):

| id | label | hook (verified in `spike/FINDINGS.md` A.2) |
|---|---|---|
| `process_start` | Process start | return location after `ActivityThread.waitForDebugger` in the main thread's `handleBindApplication` frame (found by method name in the stack, thread-filtered) |

`Hook` therefore gains `val afterReturn: Boolean = false` (stop when the hooked method returns to its caller, implemented as an entry breakpoint that arms a thread-filtered caller-return breakpoint; never STEP_OUT). Each milestone fires once (first hit), then its request is deleted. A custom hook whose class is not loaded yet uses a `ClassPrepareRequest`. A custom hook that cannot be resolved is reported as a FAILED step with hint "check class and method name", without failing the session. After the last milestone: delete all requests, resume, dispose, remove forward, disarm. Milestone not reached within `milestoneTimeoutSec` → step FAILED "not reached", session detaches cleanly and keeps earlier snapshots. Leftover check uses `dumpsys activity | grep mDebugApp` (not `settings`). Suppress JDI's `Ignoring cmd …/199/1` stderr noise.
